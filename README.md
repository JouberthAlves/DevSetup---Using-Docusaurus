# DevSetup

A fresh Windows 11 install is not a blank slate. It ships Copilot, Xbox, inbox games, and a browser I do not use. Every time I reinstall, I used to reconstruct the same toolchain from memory: Windows install and activation, the app list, Git, Node, VS Code, Claude, Obsidian.

This repo is that recipe, written down once and published as a static docs site. The docs are the product. Docusaurus is how they stay navigable.

## What this is

Nine pages, in the order I actually run them:

| Step | Doc | What I do |
| --- | --- | --- |
| 0 | [Start here](docs/intro.md) | The order, what to prepare, and a checklist for the whole machine. |
| 1 | [Install Windows 11](docs/install-windows.md) | Official media on a USB drive, clean install, updates and drivers. |
| 2 | [Activate Windows](docs/activate-windows.md) | Genuine activation: digital licence, retail key, OEM key. `slmgr` checks and error codes. |
| 3 | [Clean Windows](docs/windows-cleanup.md) | Strip bundled AI, Xbox, preinstalled games, and the Edge **browser**. Keep WebView2, Store, Terminal, Brave. Restore point first. AppBuster is not a "select all". |
| 4 | [Apps to download](docs/apps.md) | Every app as a `winget` id, a one-script install, fonts, and `winget export`. |
| 5 | [Git & Node](docs/git-node.md) | git-scm, SSH to GitHub, Node via **nvm-windows LTS**, then `pnpm` and `bun` as globals. |
| 6 | [VS Code](docs/vscode.md) | JetBrains Mono, One Dark Pro Night Flat, Prettier on save, extensions and the full `settings.json`. |
| 7 | [Claude](docs/claude-setup.md) | Claude desktop, Claude Code CLI, the VS Code extension, config files, permissions, skills and MCP. |
| 8 | [Obsidian](docs/obsidian.md) | A Git-backed vault, theme, plugins, `.gitignore`, and an `AGENTS.md` so Claude can work on it. |

This is **my** machine, not a corporate image. Follow it if the tradeoffs match yours. Uninstalling system apps can break widgets, the Store, or Windows Update; Edge often reinstalls after an update. Activation covers licences you own only.

## How the site is built

Classic Docusaurus template, then the parts that are not the template:

- **Docusaurus 3.10** (`classic` preset) with the blog plugin **off**. Docs live in `docs/`; the sidebar is autogenerated from that folder (`sidebars.ts`). English only — `locales: ['en']`.
- **TypeScript** for `docusaurus.config.ts` and the homepage (`src/pages/index.tsx`). `pnpm typecheck` is a real script, not decoration.
- **`@docusaurus/faster` + `future.v4`**. Rspack persistent cache is **off** (`rspackPersistentCache: false`). On Windows the cache was racing HMR (`cssExtractHmr.js` missing, “Acesso negado”). Faster compile stays; the disk cache does not.
- **Infima**, not a custom design system. Brand navy is `--ifm-color-primary: #003366` in `src/css/custom.css`, with a lighter scale under `[data-theme='dark']`. The hero uses the same navy. Navbar logos are `src` / `srcDark` so the wordmark survives both modes.
- **SVGs as React components** (`import … from "@site/static/img/….svg"`). Animations are CSS + SMIL. Freepik IDs do not survive SVGR/SVGO, so motion targets `data-part` attributes instead of `#id`.

```ts
future: {
  v4: true,
  faster: {
    rspackPersistentCache: false,
  },
},
```

## Layout of the repo

```
docs/                 the guide (start here → install → … → obsidian)
src/pages/index.tsx   homepage: SVGR illustrations + Get Started → /docs/intro
src/css/custom.css    Infima tokens, hero, SVG animation
static/img/           logos, illustrations, README hero
docusaurus.config.ts  site title, Faster, navbar, blog: false
sidebars.ts           autogenerated from docs/
```

Markdown in `docs/` is the source of truth. This README does not repeat the AppBuster list or the VS Code `settings.json`.

## Run it

Node **20+**. This repo is installed with **pnpm**.

```bash
pnpm install
pnpm start
```

```bash
pnpm build
pnpm typecheck
```

If Faster’s cache ever goes stale after a crash:

```bash
pnpm docusaurus clear
```
